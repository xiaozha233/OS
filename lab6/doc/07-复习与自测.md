## 1. 快速复习卡 [S82]

### 1.1 核心概念速查

| 概念 | 定义 | 关键点 |
|:---|:---|:---|
| **进程状态** | UNINIT → RUNNABLE ⇄ SLEEPING → ZOMBIE | 只有 RUNNABLE 才能被调度 |
| **主动调度** | 进程自愿让出 CPU | wait/sleep/lock |
| **被动调度** | 外部中断触发调度 | 时钟中断、系统调用返回 |
| **need_resched** | 调度标志位 | trap 返回时检查 |
| **sched_class** | 调度类结构体 | 函数指针实现多态 |
| **run_queue** | 运行队列 | 链表 + 斜堆两种结构 |
| **time_slice** | 时间片 | 用完触发调度 |
| **RR 调度** | 时间片轮转 | FIFO + 时间片 |
| **Stride 调度** | 步进调度 | 选 stride 最小的进程 |
| **BIG_STRIDE** | 大步幅常数 | 0x7FFFFFFF |

[Fig·S82-1]: 核心概念速查表

### 1.2 关键公式

| 公式 | 说明 |
|:---|:---|
| $\text{pass} = \frac{\text{BIG\_STRIDE}}{\text{priority}}$ | Stride 算法步幅计算 |
| $\text{stride}^{\text{new}} = \text{stride}^{\text{old}} + \text{pass}$ | 选中后更新 stride |
| $\frac{n_1}{n_2} \approx \frac{p_1}{p_2}$ | 调度次数与优先级成正比 |
| $\text{BIG\_STRIDE} \leq 2^{31} - 1$ | 保证溢出后仍能正确比较 |

### 1.3 五个核心函数记忆口诀

```
初始化 init    - 空队列准备好
入队 enqueue   - 进程排队尾
出队 dequeue   - 进程离队去
选择 pick_next - 队头/最小选
时钟 proc_tick - 减片设标志
```

## 3. 代码快速参考 [S84]

### 3.1 RR 调度核心代码

```c
// RR_init
list_init(&(rq->run_list));
rq->proc_num = 0;

// RR_enqueue
list_add_before(&(rq->run_list), &(proc->run_link));
if (proc->time_slice == 0 || proc->time_slice > rq->max_time_slice)
    proc->time_slice = rq->max_time_slice;
proc->rq = rq;
rq->proc_num++;

// RR_dequeue
list_del_init(&(proc->run_link));
rq->proc_num--;

// RR_pick_next
list_entry_t *le = list_next(&(rq->run_list));
if (le != &(rq->run_list))
    return le2proc(le, run_link);
return NULL;

// RR_proc_tick
if (proc->time_slice > 0) proc->time_slice--;
if (proc->time_slice == 0) proc->need_resched = 1;
```

### 3.2 Stride 调度核心代码

```c
// BIG_STRIDE
#define BIG_STRIDE 0x7FFFFFFF

// 比较函数
int32_t c = p->lab6_stride - q->lab6_stride;
return (c > 0) ? 1 : ((c == 0) ? 0 : -1);

// stride_pick_next (斜堆)
if (rq->lab6_run_pool == NULL) return NULL;
struct proc_struct *p = le2proc(rq->lab6_run_pool, lab6_run_pool);
if (p->lab6_priority == 0)
    p->lab6_stride += BIG_STRIDE;
else
    p->lab6_stride += BIG_STRIDE / p->lab6_priority;
return p;
```

### 3.3 关键初始化代码

```c
// alloc_proc 中的 Lab6 初始化
```

## 4. 常见错误汇总 [S85]

### 4.1 概念错误

| 错误理解 | 正确理解 |
|:---|:---|
| 时钟中断直接切换进程 | 时钟中断设标志，trap 返回时切换 |
| RUNNABLE = 正在运行 | RUNNABLE 包括就绪和运行 |
| Stride 越大越先调度 | Stride 越小越先调度 |
| priority 越大 pass 越大 | priority 越大 pass 越小 |
| idle 进程也在运行队列 | idle 进程不入队 |

### 4.2 代码错误

| 错误代码 | 正确代码 | 说明 |
|:---|:---|:---|
| `list_add_after(head, elm)` | `list_add_before(head, elm)` | 插入队尾 |
| `if (a->stride < b->stride)` | `if ((int32_t)(a->stride - b->stride) < 0)` | 溢出处理 |
| `proc->time_slice = 0;` | `proc->time_slice = max_time_slice;` | 入队重置 |
| `return list_next(head);` | `return le2proc(le, run_link);` | 需要转换 |

### 5.1 判断题

**Q1**：在 ucore 中，内核态代码是可以被抢占的。

<details>
<summary>答案</summary>
❌ 错误。ucore 的内核态是不可抢占的，只有用户态陷入时才检查调度。
</details>

**Q2**：RR 调度算法可以保证每个进程最终都会被调度到。

<details>
<summary>答案</summary>
✅ 正确。RR 是轮转调度，每个进程都会轮到。
</details>

**Q3**：在 Stride 调度中，优先级为 0 的进程永远不会被调度。

<details>
<summary>答案</summary>
❌ 错误。代码中对 priority=0 做了特殊处理，stride += BIG_STRIDE。
</details>

**Q4**：`sched_class_proc_tick` 函数会直接调用 `schedule()` 进行进程切换。

<details>
<summary>答案</summary>
❌ 错误。它只设置 need_resched 标志，调度在 trap 返回时进行。
</details>

**Q5**：斜堆的 `pick_next` 操作时间复杂度是 O(1)。

<details>
<summary>答案</summary>
✅ 正确。堆顶就是最小元素，直接返回即可。
</details>

### 5.3 开放题

**Q11**：描述从时钟中断发生到进程切换完成的完整流程。

<details>
<summary>参考答案</summary>

1. 时钟中断发生，硬件保存用户态寄存器
2. 进入 trap 函数
3. 调用 interrupt_handler，处理 IRQ_S_TIMER
4. 调用 sched_class_proc_tick(current)
5. proc_tick 减少 time_slice，若为 0 则设 need_resched=1
6. trap 返回前检查 in_kernel 和 need_resched
7. 若 need_resched=1 且来自用户态，调用 schedule()
8. schedule 中 enqueue 当前进程，pick_next 选择新进程
9. dequeue 新进程，调用 proc_run 执行切换
10. switch_to 保存/恢复内核上下文
11. 新进程继续执行，最终返回用户态

</details>

**Q12**：如何设计一个"多级反馈队列"调度算法？

<details>
<summary>参考答案</summary>

**设计思路**：

1. **数据结构**：
   - 多个运行队列，每个队列一个优先级
   - 每个队列使用 RR 调度
   - 高优先级队列时间片小，低优先级队列时间片大

2. **调度规则**：
   - 新进程放入最高优先级队列
   - 用完时间片降级到下一级队列
   - 主动让出 CPU 的进程升级
   - 优先调度高优先级队列

3. **修改点**：
   - run_queue 改为数组
   - 添加进程优先级字段
   - enqueue 根据优先级选择队列
   - pick_next 从高到低遍历队列
   - proc_tick 处理降级逻辑

</details>

**Q13**：证明 Stride 算法的调度次数与优先级成正比。

<details>
<summary>参考答案</summary>

设有 n 个进程，优先级分别为 $p_1, p_2, ..., p_n$。

步幅：$\text{pass}_i = \frac{B}{p_i}$

经过 T 时间后，设进程 i 被调度 $n_i$ 次，则：
$$\text{stride}_i = n_i \times \text{pass}_i = n_i \times \frac{B}{p_i}$$

由于调度器总是选择 stride 最小的进程，在足够长的时间后，所有进程的 stride 趋于相等：
$$\text{stride}_1 \approx \text{stride}_2 \approx ... \approx \text{stride}_n$$

因此：
$$n_1 \times \frac{B}{p_1} \approx n_2 \times \frac{B}{p_2}$$
$$\frac{n_1}{n_2} \approx \frac{p_1}{p_2}$$

证毕：调度次数之比等于优先级之比。

</details>
