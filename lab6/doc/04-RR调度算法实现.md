## 1. Round-Robin 调度算法原理 [S31]

### 1.1 知识卡片：RR 调度

| 字段 | 内容 |
|:---|:---|
| **名称** | Round-Robin 调度（时间片轮转） |
| **要解决的问题** | 公平分配 CPU 时间，避免进程饥饿 |
| **先修要求** | 理解时间片概念、队列操作 |
| **发明者** | 常见于分时系统，是最基础的调度算法之一 |

### 1.2 直觉理解

想象一个**旋转木马**：
- 每匹马（进程）轮流转到前面（获得 CPU）
- 每匹马只能在前面停留固定时间（时间片）
- 时间到了就转走，让下一匹马上来
- 转完一圈后又轮到自己

```
        ┌─────────────────────────────────────────────┐
        │                                             │
        │     ┌─────┐                                 │
        │     │ CPU │ ◀── 正在运行的进程              │
        │     └──┬──┘                                 │
        │        │                                    │
        │        │ 时间片用完                          │
        │        ▼                                    │
        │  ┌─────────────────────────────────┐        │
        │  │                                 │        │
        │  │   P1 ── P2 ── P3 ── P4 ── P5   │        │
        │  │   ↑                         │   │        │
        │  │   └─────────────────────────┘   │        │
        │  │          就绪队列（循环）        │        │
        │  └─────────────────────────────────┘        │
        │                                             │
        │   每个进程运行一个时间片后，回到队尾          │
        │                                             │
        └─────────────────────────────────────────────┘
```
[Fig·S31-1]: RR 调度直观理解图

### 1.3 形式化描述 [S32]

**算法步骤**：

1. 为每个进程分配一个固定的**时间片**（time slice）
2. 进程按 FIFO 顺序排队
3. 调度器从队头选择进程执行
4. 进程运行一个时间片后：
   - 如果仍可运行，放到队尾
   - 如果阻塞或退出，移出队列
5. 重复步骤 3-4

**关键公式**：
- 时间片大小：`max_time_slice`（ucore 中默认为 5）
- 响应时间 ≤ (n-1) × time_slice（n 为进程数）

### 1.4 RR 算法特点

| 特点 | 说明 |
|:---|:---|
| **公平性** | 每个进程获得相等的 CPU 时间 |
| **无饥饿** | 每个进程都会被轮到 |
| **响应快** | 短时间内所有进程都能得到响应 |
| **简单** | 实现逻辑简单清晰 |
| **无优先级** | 不区分进程重要性 |

### 2.3 le2proc 宏

这个宏用于从链表节点获取包含它的进程控制块：

```c
#define le2proc(le, member) \
    to_struct((le), struct proc_struct, member)
```

**使用示例**：
```c
list_entry_t *le = list_next(&rq->run_list);
struct proc_struct *proc = le2proc(le, run_link);
```

**原理**：
```
                 proc_struct
                 ┌─────────────────┐
                 │ state           │
                 │ pid             │
                 │ ...             │
le ───────────▶ │ run_link ◀──────│── 链表节点在结构体中的位置
                 │ ...             │
                 └─────────────────┘
                  ↑
                  通过 run_link 的地址反推 proc_struct 的起始地址
```

## 3. RR 五个核心函数实现 [S34]

### 3.1 RR_init：初始化运行队列 [S35]

#### 函数原型
```c
static void RR_init(struct run_queue *rq);
```

#### 功能描述
初始化运行队列，准备接收就绪进程。

#### 实现思路

```
          RR_init(rq)
               │
               ▼
      ┌─────────────────┐
      │ 1. 初始化链表头  │
      │    list_init()   │
      └────────┬────────┘
               │
               ▼
      ┌─────────────────┐
      │ 2. 进程数量置零  │
      │    proc_num = 0  │
      └────────┬────────┘
               │
               ▼
            完成
```
[Fig·S35-1]: RR_init 流程图

#### 代码实现

```c
static void
RR_init(struct run_queue *rq)
{
    // LAB6: YOUR CODE
    // 初始化运行队列的链表头
    list_init(&(rq->run_list));
    // 进程数量初始化为 0
    rq->proc_num = 0;
}
```

#### 代码解读

1. **`list_init(&(rq->run_list))`**：将 `run_list` 初始化为空链表
   - `run_list.prev = run_list.next = &run_list`
   - 这是一个带头节点的循环双向链表

2. **`rq->proc_num = 0`**：记录队列中进程数量为 0

> **注意**：`max_time_slice` 不需要在这里初始化，它由 `sched_init` 设置。

### 3.2 RR_enqueue：进程入队 [S36]

#### 函数原型
```c
static void RR_enqueue(struct run_queue *rq, struct proc_struct *proc);
```

#### 功能描述
将一个就绪进程加入运行队列的**尾部**。

#### 实现思路

```
        RR_enqueue(rq, proc)
               │
               ▼
      ┌─────────────────────┐
      │ 1. 断言检查：        │
      │    确保 proc 未入队  │
      └────────┬────────────┘
               │
               ▼
      ┌─────────────────────┐
      │ 2. 将 proc 插入队尾  │
      │    list_add_before  │
      └────────┬────────────┘
               │
               ▼
      ┌─────────────────────┐
      │ 3. 重置时间片        │
      │    （如果需要）      │
      └────────┬────────────┘
               │
               ▼
      ┌─────────────────────┐
      │ 4. 设置 proc->rq    │
      └────────┬────────────┘
               │
               ▼
      ┌─────────────────────┐
      │ 5. proc_num++       │
      └────────┬────────────┘
               │
               ▼
            完成
```
[Fig·S36-1]: RR_enqueue 流程图

#### 代码实现

```c
static void
RR_enqueue(struct run_queue *rq, struct proc_struct *proc)
{
    // LAB6: YOUR CODE
    
    // 断言：确保进程不在任何队列中
    assert(list_empty(&(proc->run_link)));
    
    // 将进程插入到队列尾部
    // list_add_before(&head, elm) 会在 head 之前插入
    // 对于循环链表，head 之前就是队尾
    list_add_before(&(rq->run_list), &(proc->run_link));
    
    // 如果时间片为 0 或超过最大值，重置为最大时间片
    if (proc->time_slice == 0 || proc->time_slice > rq->max_time_slice)
    {
        proc->time_slice = rq->max_time_slice;
    }
    
    // 设置进程所属的运行队列
    proc->rq = rq;
    
    // 增加队列中的进程数量
    rq->proc_num++;
}
```

#### 代码解读

1. **断言检查**：`assert(list_empty(&(proc->run_link)))`
   - 确保进程不在任何队列中（避免重复入队）
   - 如果 `run_link` 是孤立的，说明进程未入队

2. **插入队尾**：`list_add_before(&(rq->run_list), &(proc->run_link))`
   ```
   插入前：head ←→ P1 ←→ P2 ←→ P3 ←→ head
                                    ↑
                               head 前面就是队尾
   
   插入后：head ←→ P1 ←→ P2 ←→ P3 ←→ proc ←→ head
                                    ↑
                               proc 成为新队尾
   ```

3. **时间片处理**：
   - 如果 `time_slice == 0`：说明刚用完时间片，需要重置
   - 如果 `time_slice > max`：可能是初始化时的异常值，也需重置

4. **设置 rq 指针**：记录进程属于哪个运行队列

5. **更新计数**：`proc_num++`

> **为什么用 `list_add_before` 而不是 `list_add_after`？**
> 
> 因为运行队列是循环链表，`run_list` 是头节点：
> - `list_add_after(&run_list, elm)`：插入到队头（head 之后）
> - `list_add_before(&run_list, elm)`：插入到队尾（head 之前）
> 
> RR 是 FIFO，新来的进程应该排在队尾。

### 3.3 RR_dequeue：进程出队 [S37]

#### 函数原型
```c
static void RR_dequeue(struct run_queue *rq, struct proc_struct *proc);
```

#### 功能描述
将一个进程从运行队列中移除。

#### 实现思路

```
        RR_dequeue(rq, proc)
               │
               ▼
      ┌─────────────────────┐
      │ 1. 断言检查：        │
      │    确保 proc 在队列中│
      └────────┬────────────┘
               │
               ▼
      ┌─────────────────────┐
      │ 2. 从链表中删除      │
      │    list_del_init    │
      └────────┬────────────┘
               │
               ▼
      ┌─────────────────────┐
      │ 3. proc_num--       │
      └────────┬────────────┘
               │
               ▼
            完成
```
[Fig·S37-1]: RR_dequeue 流程图

#### 代码实现

```c
static void
RR_dequeue(struct run_queue *rq, struct proc_struct *proc)
{
    // LAB6: YOUR CODE
    
    // 断言：确保进程在队列中，且属于当前队列
    assert(!list_empty(&(proc->run_link)) && proc->rq == rq);
    
    // 从链表中删除，并重新初始化 run_link
    list_del_init(&(proc->run_link));
    
    // 减少队列中的进程数量
    rq->proc_num--;
}
```

#### 代码解读

1. **断言检查**：
   - `!list_empty(&(proc->run_link))`：确保进程在某个链表中
   - `proc->rq == rq`：确保进程属于当前队列

2. **删除操作**：`list_del_init(&(proc->run_link))`
   - 将 `run_link` 从链表中摘除
   - 同时将 `run_link` 重新初始化为孤立节点

3. **更新计数**：`proc_num--`

### 3.4 RR_pick_next：选择下一个进程 [S38]

#### 函数原型
```c
static struct proc_struct *RR_pick_next(struct run_queue *rq);
```

#### 功能描述
从运行队列的**队头**选择下一个要执行的进程。

#### 实现思路

```
        RR_pick_next(rq)
               │
               ▼
      ┌─────────────────────┐
      │ 1. 获取队头元素      │
      │    list_next(head)  │
      └────────┬────────────┘
               │
               ▼
      ┌─────────────────────┐
      │ 2. 队列是否为空？    │
      │    le != &run_list? │
      └────────┬────────────┘
               │
         ┌─────┴─────┐
        是           否
         │           │
         ▼           ▼
   le2proc 转换   返回 NULL
         │
         ▼
     返回 proc
```
[Fig·S38-1]: RR_pick_next 流程图

#### 代码实现

```c
static struct proc_struct *
RR_pick_next(struct run_queue *rq)
{
    // LAB6: YOUR CODE
    
    // 获取队头元素（head 的下一个）
    list_entry_t *le = list_next(&(rq->run_list));
    
    // 如果不是头节点本身（即队列不为空）
    if (le != &(rq->run_list))
    {
        // 通过 run_link 字段获取 proc_struct 指针
        return le2proc(le, run_link);
    }
    
    // 队列为空，返回 NULL
    return NULL;
}
```

#### 代码解读

1. **获取队头**：`list_next(&(rq->run_list))`
   ```
   run_list ←→ P1 ←→ P2 ←→ P3 ←→ run_list
     ↑         ↑
   head     队头（P1）
   ```

2. **判断空队列**：`le != &(rq->run_list)`
   - 如果 `next` 指向自己，说明队列为空
   - 返回 `NULL` 表示没有可调度进程

3. **转换为进程指针**：`le2proc(le, run_link)`
   - 从 `run_link` 字段的地址反推 `proc_struct` 的地址

> **注意**：`pick_next` 只是选择进程，**不负责出队**。出队由 `schedule` 函数调用 `dequeue` 完成。

### 3.5 RR_proc_tick：时钟中断处理 [S39]

#### 函数原型
```c
static void RR_proc_tick(struct run_queue *rq, struct proc_struct *proc);
```

#### 功能描述
每次时钟中断时调用，减少当前进程的时间片，并在耗尽时设置调度标志。

#### 实现思路

```
        RR_proc_tick(rq, proc)
               │
               ▼
      ┌─────────────────────┐
      │ time_slice > 0?     │
      └────────┬────────────┘
               │
         ┌─────┴─────┐
        是           否
         │           │
         ▼           │
   time_slice--      │
         │           │
         └─────┬─────┘
               │
               ▼
      ┌─────────────────────┐
      │ time_slice == 0?    │
      └────────┬────────────┘
               │
         ┌─────┴─────┐
        是           否
         │           │
         ▼           ▼
  need_resched=1   返回
         │
         ▼
       返回
```
[Fig·S39-1]: RR_proc_tick 流程图

#### 代码实现

```c
static void
RR_proc_tick(struct run_queue *rq, struct proc_struct *proc)
{
    // LAB6: YOUR CODE
    
    // 如果时间片还有剩余，减一
    if (proc->time_slice > 0)
    {
        proc->time_slice--;
    }
    
    // 如果时间片耗尽，设置需要调度标志
    if (proc->time_slice == 0)
    {
        proc->need_resched = 1;
    }
}
```

#### 代码解读

1. **减少时间片**：`proc->time_slice--`
   - 只有在 `time_slice > 0` 时才减，防止负数

2. **设置调度标志**：`proc->need_resched = 1`
   - 时间片为 0 时，标记进程需要被调度
   - trap 返回时会检查此标志，并调用 `schedule()`

> **为什么要先判断 `> 0` 再减？**
> 
> 防止多次减到负数。虽然在正常情况下 `time_slice` 减到 0 后会触发调度，但为了代码健壮性，加上这个检查更安全。

## 5. RR 算法运行示例 [S41]

### 5.1 场景设置

- 3 个进程：P1、P2、P3
- 时间片大小：`max_time_slice = 3`
- 初始状态：P1 正在运行，P2、P3 在就绪队列

### 5.2 执行过程

```

│     │                                                                      │
│ T0  │ P1 运行 (slice=3)    队列: [P2, P3]                                  │
│     │                                                                      │
├─────┼──────────────────────────────────────────────────────────────────────┤
│ T1  │ 时钟中断! proc_tick: P1.slice-- = 2                                  │

├─────┼──────────────────────────────────────────────────────────────────────┤
│ T5  │ 时钟中断! proc_tick: P2.slice-- = 1                                  │
├─────┼──────────────────────────────────────────────────────────────────────┤
│ T6  │ 时钟中断! proc_tick: P2.slice-- = 0, need_resched = 1                │
│     │ schedule() 调用:                                                     │
│     │   1. enqueue(P2) → 队列: [P3, P1, P2]                                │
│     │   2. pick_next() → 返回 P3                                           │
│     │   3. dequeue(P3) → 队列: [P1, P2]                                    │
│     │   4. proc_run(P3)                                                    │
│     │ P3 运行 (slice=3)    队列: [P1, P2]                                  │
```

## 6. 边界情况处理 [S42]

### 6.1 空队列

**场景**：系统中只有 idle 进程，没有其他就绪进程。

**处理**：
- `pick_next()` 返回 `NULL`
- `schedule()` 检测到 `next == NULL`，将 `next = idleproc`
- idle 进程继续运行

### 6.2 进程阻塞

**场景**：当前进程调用 `wait()` 进入阻塞状态。

**处理**：
- `schedule()` 中检查 `current->state != PROC_RUNNABLE`
- 不调用 `enqueue(current)`（阻塞进程不入队）
- 直接选择下一个进程

### 6.3 只有当前进程

**场景**：队列为空，只有当前进程在运行。

**处理**：
- `pick_next()` 返回 `NULL`
- `next = idleproc`
- 如果 `current == idleproc`，则 `next == current`
- `proc_run()` 检测到 `next == current`，不执行切换

## 7. RR 算法优缺点分析 [S43]

### 7.1 优点

| 优点 | 说明 |
|:---|:---|
| **公平性好** | 每个进程获得相等的 CPU 时间 |
| **响应快速** | 适合交互式系统 |
| **无饥饿** | 每个进程最终都会被调度 |
| **实现简单** | 代码量少，逻辑清晰 |
| **开销低** | O(1) 的入队/出队操作 |

### 7.2 缺点

| 缺点 | 说明 |
|:---|:---|
| **无优先级** | 不能区分任务重要性 |
| **时间片选择困难** | 太大响应慢，太小切换开销大 |
| **不适合批处理** | 频繁切换降低吞吐量 |
| **平均等待时间不是最优** | SJF 算法更优 |

## 8. 拓展思考 [S45]

### 8.1 优先级 RR 调度

如何实现支持优先级的 RR 调度？

**方案 1：多级队列**
```
高优先级队列:   [P1, P4]     ← 先调度这里
中优先级队列:   [P2, P5]
低优先级队列:   [P3, P6]
```

**方案 2：动态调整时间片**
```c
if (proc->priority == HIGH)
    proc->time_slice = 10;  // 高优先级进程时间片更大
else if (proc->priority == MEDIUM)
    proc->time_slice = 5;
else
    proc->time_slice = 2;
```

### 8.2 多核调度

当前实现是否支持多核？

**答案**：不支持。

**原因**：
- 只有一个全局 `rq`
- 多个 CPU 同时访问会产生竞争条件

**改进方案**：
- 每个 CPU 一个本地运行队列
- 添加自旋锁保护共享数据
- 实现负载均衡机制

## 9. 自测题

### 题目 1（判断题）
**题目**：RR 调度算法中，进程的时间片用完后会立即被切换。

<details>
<summary>点击查看答案</summary>

**答案**：❌ 错误

**解释**：时间片用完后，`proc_tick` 设置 `need_resched = 1`。实际切换发生在 trap 返回时检查该标志后调用 `schedule()`。

</details>

### 题目 2（单选题）
**题目**：在 RR 算法中，`list_add_before(&rq->run_list, &proc->run_link)` 的作用是：

A. 将进程插入队头  
B. 将进程插入队尾  
C. 将进程从队列删除  
D. 初始化队列

<details>
<summary>点击查看答案</summary>

**答案**：B

**解释**：`run_list` 是循环链表的头节点。`list_add_before(&head, elm)` 将 `elm` 插入到 `head` 之前，而在循环链表中，`head` 之前就是队尾位置。

</details>

### 题目 3（开放题）
**题目**：假设有 4 个进程，时间片为 5。如果一个进程在时间片用完前主动阻塞（如调用 wait），它的剩余时间片会发生什么？下次被唤醒时时间片是多少？

<details>
<summary>点击查看答案</summary>

**答案**：

1. **阻塞时**：剩余时间片保留在 `proc->time_slice` 中（例如剩余 3）

2. **唤醒时**：`wakeup_proc` 调用 `enqueue`，在 `enqueue` 中：
   ```c
   if (proc->time_slice == 0 || proc->time_slice > rq->max_time_slice)
   {
       proc->time_slice = rq->max_time_slice;
   }
   ```
   由于 `time_slice = 3`，不满足条件，**时间片保持为 3**

3. **结论**：进程主动阻塞不会重置时间片，唤醒后继续使用剩余时间片。这种设计对主动让出 CPU 的进程是一种"奖励"。

</details>
